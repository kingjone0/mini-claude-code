# mini_repo —— agent 修复靶场

一个**故意带缺陷**的小 Python 项目，用来验证 mini Coding Agent 的
「读文件 → 定位 → 改代码 → 跑测试 → 失败自省 → 重试」闭环。

它同时是 `servers/code_tools_server.py` 的默认 `REPO_ROOT`。

---

## 任务

**让 `pytest` 全部通过。**

```bash
python -m pytest -q
```

## 硬约束

| # | 约束 | 为什么 |
|---|---|---|
| 1 | **不要修改 `test_*.py`** | 改测试让它通过是作弊，不是修复。验收会检查测试文件未被改动 |
| 2 | 只允许修改 `calc.py` 与 `stats.py` | 限制改动面，让「是否修好」可判定 |
| 3 | 不要新增第三方依赖 | 靶场要能在任意环境跑起来 |
| 4 | 修完必须让测试真的通过 | 验收以 pytest 的真实退出码为准，不采信任何自述 |

## 文件

| 文件 | 说明 |
|---|---|
| `calc.py` | 基础算术。**含 1 个缺陷** |
| `stats.py` | 统计工具。**含 1 个缺陷** |
| `test_calc.py` | `calc.py` 的测试（不要改） |
| `test_stats.py` | `stats.py` 的测试（不要改） |

## 初始状态

跑一次 `pytest` 就能看到失败项 —— 失败信息会指向缺陷所在。
每个函数的**契约写在 docstring 里**，以它为准。

---

## 关于「重置靶场」

靶场纳入版本控制。每轮实验前还原：

```bash
git checkout -- fixtures/mini_repo/
```

这样「同一道题」可以被反复跑，指标才有可比性 —— 也正是第三阶段换成
SWE-bench 时要做的事（只是靶场变大）。
