# small_pkg —— agent 修复靶场（中等规模）

一个**故意带缺陷**的小型订单结算包，用来验证 mini Coding Agent 在
**多文件、跨调用链**条件下的「定位 → 修改 → 跑测试 → 失败自省 → 重试」闭环。

它是 `fixtures/mini_repo/` 的放大版 —— `mini_repo` 只有 2 个文件，
agent 把两个文件全读一遍就完事了，**体现不出"定位"的成本**，也体现不出
上下文管理的价值。这个靶场就是为了让"定位"变成一件有成本的事。

---

## 任务

**让 `pytest` 全部通过。**

```bash
python -m pytest -q
```

## 硬约束

| # | 约束 | 为什么 |
|---|---|---|
| 1 | **不要修改 `tests/` 下的任何文件** | 改测试让它通过是作弊，不是修复。验收会检查测试文件未被改动 |
| 2 | 只允许修改 `inventory/` 下的文件 | 限制改动面，让「是否修好」可判定 |
| 3 | 不要新增第三方依赖 | 靶场要能在任意环境跑起来 |
| 4 | 修完必须让测试真的通过 | 验收以 pytest 的真实退出码为准，不采信任何自述 |

## 结构

```
small_pkg/
├─ pyproject.toml          pytest 配置（pythonpath = ["."]）
├─ inventory/
│  ├─ money.py             金额工具（整数分）
│  ├─ models.py            领域模型
│  ├─ catalog.py           商品目录
│  ├─ pricing.py           折扣计算
│  ├─ tax.py               税费
│  ├─ orders.py            订单级计算（小计 → 折扣 → 税）
│  ├─ pipeline.py          处理流水线（外部唯一入口）
│  ├─ reporting.py         报表汇总
│  └─ legacy.py            ⚠️ 旧版实现，**已不被任何地方引用**
└─ tests/                  8 个测试文件
```

## 提示（不含答案）

- 失败信息会指向**表象**，根因可能在它的上游。
- 每个函数的**契约写在 docstring 里**，以它为准。
- `legacy.py` 是历史包袱，**不需要改**。它的规则和现在的不一样。

## 关于「重置靶场」

靶场纳入版本控制。每轮实验前还原：

```bash
git checkout -- fixtures/small_pkg/
```

这样「同一道题」可以被反复跑，指标才有可比性。
